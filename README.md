# dotfiles

Personal Omarchy configuration — Hyprland keybinds, terminal fonts, bar widgets,
and the niri-style scrolling workspaces.

## Layout

```
config/hypr/          bindings, input, look-and-feel, monitors (Lua)
config/alacritty|foot|kitty|ghostty/   terminal font sizes
config/omarchy/       bar layout (shell.json), font size (shell.toml)
bin/                  helper scripts on PATH
state/                workspace layout rules (scrolling on workspaces 1-9)
scripts/              helpers called by install.sh
plugins.txt           third-party bar widgets + their git URLs
theme.txt             theme display name
```

## New machine

```sh
git clone <this-repo> ~/dotfiles
cd ~/dotfiles && ./install.sh
```

`install.sh` links `config/` and `bin/` files to their destinations, copies the
mutable `state/` files, and backs up anything it replaces. It also sets the
theme, installs and enables the plugins, then reloads Hyprland and fails if
`hyprctl configerrors` reports anything. Use `--files-only` to apply the files
without changing the theme or plugin state.

Preview first with `./install.sh --dry-run`.

## Day to day

Files under `~/.config` and `~/.local/bin` link to this checkout, so edits
there update the repo immediately. `state/` is copied because Omarchy rewrites
workspace rules. To save copied state or configs an app replaced with regular files:

```sh
./install.sh --save     # copy machine -> repo
git add -A && git commit
```

Going the other way (after `git pull`, or to reset drift):

```sh
./install.sh            # copy repo -> machine
```

`--save` only copies paths already present in the repo, so it never pulls in
unrelated files from `~/.config`.

## Notes

- **Symlinked config and executables.** Edits to linked files immediately change
  this checkout. Links point to this clone, so rerun `./install.sh` after moving
  the clone. Some Omarchy refreshes may write through a link into the repo; rerun
  the installer if an app replaces a link with a regular file.
- **Copied state.** `state/` stays as regular files because Omarchy regenerates
  workspace layout rules when you switch layouts. Use `./install.sh --save` to
  copy those changes back into the repo.
- **Bar workspaces:** `config/omarchy/shell.json` keeps `tornikegomareli.spaces` and omits
  the built-in `omarchy.workspaces` widget to avoid duplicate workspace indicators.
- **`state/`** holds `workspace-layouts/{1-9}.lua`, which make all numbered
  workspaces use the scrolling (niri-style) layout. They are regenerated by
  `SUPER + ALT + L` (`omarchy-hyprland-workspace-layout-toggle`), so a saved
  copy here is just the starting point for a new machine.
- **`scripts/`** must stay alongside `install.sh`; it resolves paths relative to
  its own location.
- Files Omarchy ships unmodified (branding, menu extensions, sample hooks,
  btop/tmux/git/starship) are deliberately not tracked.
